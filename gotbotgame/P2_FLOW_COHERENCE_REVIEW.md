## 一、审查发现的问题

### 1.1 每晚收束文本重复/断裂（产品设计总监发现）

**原流程**：`daily_return`（你做完手头的事，看了看窗外。雨还在下。）→ `private_check`（当夜。你正要熄灯——）→ `private_close`（这一夜，比想象中要长。你躺下，...想了很久。）→ `day*_close`（这一天的雨还没有停。你回到自己的房间，回想...）

**缺陷**：
| 问题 | 具体表现 |
| --- | --- |
| 雨重复 | `daily_return`"雨还在下" → `day1_close`"这一天的雨还没有停"（同一天、同义的雨描写出现两次） |
| 场景断裂 | `private_check`"你正要熄灯——" → `day1_close`"你回到自己的房间"（熄灯后回到房间，时序颠倒） |
| 时序倒错 | `private_close`"你躺下...想了很久" → `day1_close`"你回到自己的房间，回想"（躺下后又回到房间，动作倒序） |

### 1.2 第三天时间线矛盾（制作人发现）

| 节点 | 原文本 | 问题 |
| --- | --- | --- |
| day3_close | …是时候去观澜阁了。第三日暂告段落。 | 暗示玩家马上出发去观澜阁 |
| day3_summary | 三日一瞬。你坐在灯下…细细理了一遍。 | 当晚还在客栈灯下盘点，未出发 |
| fire_night_transition | 你在客栈又歇了两日。…盘算着明日动身去观澜阁… | 又过了两天还在"盘算明天去" |

**矛盾链**：day3 说马上去 → summary 当晚还没走 → transition 过了两天还在计划去。玩家困惑：到底什么时候去？

## 二、修复后效果

### 2.1 每晚流程（以 Day2 为例）

```
daily_return: "你做完手头的事。"
      ↓
private_check: "夜深了。"（判定私约，auto_route）
      ↓
private_close: "你躺下，听着窗外的雨声。"
      ↓
day2_close: "第二夜的雨也没停。你躺在床上，想着明天就是最后一天了…"
```

✅ 每个节点只负责一个动作，不重叠；时序自然（做完事→入夜→躺下→回想入睡）。

### 2.2 第三天时间线

```
day3_close:      第三夜的雨停了。你坐在床边…第三日暂告一段落。
day3_summary:    你坐在灯下，把这三日的人和事，又理了一遍。  ← 当晚灯下细节
fire_night:      三天过去，你又在客栈歇了两日。…这天入夜，你早早躺下，盘算着明天动身去观澜阁的事。夜半…走水了——
```

✅ 三天→结算（当晚灯下）→又歇两日→第五天夜走水。"观澜阁"只在 transition 出现，且明确是"明天"而非"马上"。

## 四、总监评审

### 产品设计总监
- 每晚收束链条的"雨/熄灯/回房/躺下/回想"五重重复已消除，每节点只保留一个动作，读感清爽连贯。
- 第三天时间线：day3_close 不再抢跑"去观澜阁"，transition 明确"三天过去→又歇两日→这天入夜→盘算明天动身→夜半走水"，玩家可自然理解时间跳跃。
- 私约触发路径（auto_route）的"夜深了。"→敲门→接受/拒绝→"躺下听雨"→日收束，三段式节奏保留完整。
- **评审通过。**

### 美术总监
- 文本画面去冗余后更克制："听着窗外的雨声"替代"看着窗外雨停又落，想了很久"，从视觉转向听觉，加强了雨夜客栈的沉浸感。
- 第三天 transition"三天过去，你又在客栈歇了两日"让青石积水→灯笼→两个模糊日夜的过渡画面更有留白韵味。
- **评审通过。**

### 技术总监
- 仅修改 final-dialogue 的 text 字段，分支树节点 ID/路由/speaker 未动，JSON 解析通过（102 节点，无乱码）。
- private_check 改为极简旁白缩短 auto_route 等待时间（原 "当夜\n\n你正要熄灯——" 含打字机延迟，改为 "夜深了。" 过渡更迅捷），对后续私约判定无影响。
- **评审通过。**
