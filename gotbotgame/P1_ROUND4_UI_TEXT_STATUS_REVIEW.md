# P1 MVP 第四轮修改评审 — 文案分支显示 / UI 布局 / 数值状态栏

> 日期：2026-08-09
> 依据：《清风渡-MVP文案总汇.md》（outputs/）
> 范围：`gotbotgame/`（Godot 4.x + GDScript）
> 评审流程：产品设计总监 → 技术总监 → 美术总监 → 制作人终审

---

## 一、本轮需求（4 项）

1. **文案显示**：选中选项后，旁白组件须展示对应分支内容（标题=说话人 + 分支文案）。例：第二章选归汉线 c2「我在看你的剑」，须出现「认得？」等对应回应。
2. **UI 布局**：选项不得被其他组件遮挡（第三章每时段 5 选项，d/e 曾被下方对话框盖住）；允许调整选项布局。
3. **数值显示**：左上角时间随剧情推进变化，第一、二章不显示「第 X 天 · 时段」；除洞察外新增「好感度」「碎片」计数（例：帮黎客颍整理线索选 b「皱眉：这个字不太清楚」→ 黎好感 +15、碎片 +1 累加显示）。
4. **各总监与制作人**：核查并修正其他未按文案制作的内容；全部评审通过后简短汇报。

### 2.1 文案分支显示（需求 1）

| 文件 | 修改 |

| `scripts/mvp_ui_controller.gd` | 1) `_response_node_for()` 补全 **32 个选项 → 对应对白分支节点**的映射（第二章三线 12 个 + 第三章柳喝茶 5 / 黎线索 4 / 归对坐 4 / 闲逛 3 / 伙计 4），旧映射指向 3 个已不存在的选项 ID（死代码），替换为现行分支树真实选项 ID。<br>2) 新增「回应→继续→目标节点」流程：选中选项后先在旁白处展示分支内容（说话人标题 + 文案正文），选项面板只显示一个「继续」按钮，点击后再进入目标节点——**修复了此前分支文本直接覆盖目标节点文本、导致第三章章节卡永远不显示的问题**。<br>3) 连接循环只绑定本次新增的「继续」按钮，避免误连 queue_free 延迟删除的旧按钮。 |

### 2.2 UI 布局（需求 2）

| 文件 | 修改 |
| --- | --- |
| `scenes/main.tscn` | ChoicePanel 从 (72,190,590,360) 上移至 (72,82,620,368)，可用高度 170px → **286px**；状态栏改为双行并微调位置 (36,16,760,78)，与选项面板间隔 4px，无重叠。 |

### 2.3 数值状态栏（需求 3）

| 文件 | 修改 |
| --- | --- |
| `scripts/mvp_scene_runner.gd` | 新增 `_sync_day_slot_from_node()`：按节点 ID 同步 `state.day / state.slot / state.current_slot`（`scene_daily_day1_01→第1天上午`…`scene_day3_close→第3天夜`）；行动/返回类节点继承当前天时段。另修复 `action_count` 只写 `flags` 不写 `state.action_count` 属性、导致**存档快照中行动计数恒为 0** 的问题。 |
| `scenes/status_bar.tscn` | 状态栏重构为双行：Row1=时间 + 存档/读档按钮；Row2=洞察/碎片/好感度。 |
| `scripts/status_bar.gd` | 1) 时间标签按剧情节点推进显示，**第一、二章/章节卡/结局隐藏**（`第 X 天 · 上午/下午/夜`，与文案时段卡一致，不用「晨/午/夜」）。<br>2) 新增 `碎片` 与 `柳/黎/归` 三好感计数，随 `state_changed` 实时刷新。数值本身由分支树效果驱动（如 `li_clue_b` = 黎好感 +15、碎片 +1，校验通过），此前仅缺展示。 |

### 2.4 总监核查发现并修正的其他内容（需求 4）

- 「闲逛」入口文本与分支文本重复展示（见 2.1，数据层根因）。
- 选择回应后章节卡被跳过（见 2.1，流程层根因）。
- 存档快照 action_count 失真（见 2.3）。
- 时间标签固定「第 1 天 · 晨」不随剧情变化（见 2.3）。
- 好感/碎片数据无任何 UI 反馈（见 2.3）。
