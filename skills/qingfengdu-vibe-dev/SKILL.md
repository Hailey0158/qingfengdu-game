# 清风渡 Vibe Dev — 项目约束层

## 适用范围

本 skill 只适用于工作区 `C:\Users\gh604\WorkBuddy\game-02` 的《清风渡》项目。它是 `game-studio` 与 `project-ledger` 的强制约束层，不替代二者。

凡涉及以下工作，必须先加载本 skill：

- Godot 4.x / GDScript 工程、场景、UI、存档、分支、音频与导出开发
- 角色立绘、表情、背景、UI 视觉、CG 或其他美术资产生成/修改
- BGM、SFX、环境音、音频触发与混音方案生成/修改
- 剧情、角色、场景、分支、结局、文案的新增或修改

## 唯一规范来源与优先级

每次任务开始前，按以下顺序读取最新文件，并以其内容为唯一事实来源：

1. `project-ledger.json`：任务阶段、依赖关系、可启动范围与验收交付物
2. `PRD.md`：产品边界、平台、核心玩法、美术与音频方向、技术要求
3. `PDD.md`：世界观、角色设定、场景/分支规格、UI/音频/存档/Godot 技术架构
4. `skills/game-studio/references/game-studio.md`：角色职责、评审与交付格式

规则冲突时，按以上顺序处理；需要改动已定规范时，先提出并取得用户明确批准，再同步修改相关文档与台账，不能以生成内容暗中覆盖设定。

## 强制执行流程

1. 加载 `project-ledger`，读取台账并锁定一个任务。
2. 校验该任务的 dependencies；存在未完成依赖时停止，不得启动，除非用户明确批准并行。
3. 读取 PRD、PDD 与本 skill；提取与当前任务直接有关的约束，形成简短的“约束核对清单”。
4. 按 `game-studio` 的角色与总监收口机制执行；所有输出使用规定的文件路径与格式。
5. 验收时核查：台账交付物是否真实存在、是否符合 PRD/PDD、是否没有角色/OOC/风格/技术越界。
6. 仅在验收通过后更新 `project-ledger.json` 的任务状态、完成日期、交付物和汇总。

## 不允许自由发挥

以下情况默认禁止，必须先取得用户明确的“修改 PRD/PDD”授权：

- 新增或替换主角、关键配角、势力、世界观历史、古玉机制、结局主线
- 改变柳陆书、黎客颍、归汉、谢师叔或伙计的身份、动机、关系、武器、性格和叙事结局
- 增加战斗、抽卡、收集、卡牌等 PRD 明确排除的系统
- 将引擎改离 Godot 4.x + GDScript，或绕开既定的 GameStateManager、JSON 分支、ResourceSaver/JSON 存档、AudioBus 架构
- 将视觉改离“半厚涂 + 水墨晕染边缘 + 克制留白”的古风仙侠方向，或使用不符合既定角色外观的设计
- 将音频改离“古琴/箫/笛为主，雨声/烛火/风声为环境底噪”的叙事服务原则

用户请求超出已定义内容时，应说明与哪一份规范、哪一节发生冲突，并给出“保持当前规范的实现方案”与“先修订规范后再实现”的选项；不得自行选定新设定。

## 清风渡内容硬约束

### 叙事与角色

- 核心地点：雨夜山道、清风渡客栈、观澜阁秘境；核心结构为三天九时段加最终对峙。
- 古玉以执念为食，通过“最大的愿望”吞噬意志与记忆；不可简化为普通宝物或单纯怪物。
- 柳陆书：青衫、折扇、墨竹扇面；闲散表象下等待师父与真相，言语真真假假。
- 黎客颍：红发高马尾、黑衣、长刀；寡言重诺，为寻谢前辈而来。
- 归汉：银白长发、白袍、淡蓝剑穗；名门剑修，冷静克制但在意甚多，面对谢师叔有无法回避的情感抉择。
- 伙计是被古玉利用执念侵蚀的客栈经营者；“靠门第三张桌、旧茶壶、每日续茶”是隐藏线核心意象。
- 叙事保持短句、留白、克制，不用网文化过度解释；角色行为必须可从既定动机推导。

### 美术与 UI

- 视觉基调：半厚涂、保留线稿勾神、水墨晕染边缘、青/黑/白主色；关键情绪可转暖红或冷蓝。
- 立绘：透明 PNG，至少 1600×2000 px；屏高占比 60–70%；每位主角至少平静/微笑/严肃三种表情。
- 固定角色识别：柳=青衫折扇；黎=黑衣红发与刀；归=白袍银发与淡蓝剑穗。不得互换或弱化。
- UI：仿古卷轴、半透明毛玻璃、水墨边缘、印章图标；标题书法体，正文宋体/楷体，需符合 Godot Control 节点实现与中文字体嵌入要求。

### 音频

- BGM 以古琴、箫、笛为主体，少量弦乐仅用于增强情绪；禁止与古风沉浸感冲突的强电子、现代流行或夸张史诗化处理。
- 环境底噪：雨声、烛火、风声；按场景与情绪触发，不遮蔽阅读。
- 角色映射：柳陆书互动=轻快笛声；黎客颍互动=中性弦乐；归汉互动=古琴独奏；真相揭晓=弦乐渐强。
- Godot 实现必须使用 BGM/SFX/环境音三 AudioBus 分离与独立音量控制。

### Godot 技术

- 仅使用 Godot 4.x 与 GDScript；目标导出 Web、Windows、macOS、Linux，Android 仅后续可选。
- 分支：`GameStateManager` + JSON 驱动状态机，状态包括好感度、洞察、碎片与标志；每一选择须有可追溯后果。
- 存档：关键决策前自动存档 + 多手动槽；使用 ResourceSaver 与 JSON 序列化，存档路径为 `user://`。
- 对话：RichTextLabel 打字机效果，使用 `visible_characters` 或等效安全实现；角色台词与逻辑解耦。
- 立绘：Sprite2D 或 TextureRect，表情切换以 Tween 淡入淡出，目标 200ms。
- 性能门槛：Web 首屏加载不超过 5 秒、场景切换不超过 1 秒、中文字体嵌入后渲染一致。
